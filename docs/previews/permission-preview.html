P0 · 审批结果补齐 cancelled

问题：现在只读模式下 DSH 的每次写工具调用都触发 VS Code 原生模态框，只有「允许一次 / 拒绝」两种结果，协议里的 cancelled 没有映射。

界面改动

  • 审批 UI 从 VS Code 原生模态框迁入 Webview 内嵌审批卡片（固定显示在输入框上方，与排队消息同区域）。原生模态框放不下「工具详情 + 命令预览 + 三个动作 + 取消」。
  • 卡片右上角 × 与 Esc = 取消：关闭提问，Agent 收到「用户取消」，本轮可继续对话，不视为拒绝（拒绝会告诉模型"操作被明确禁止"）。
  • 卡片展示：工具名、调用原因、命令/文件预览（只读模式下每个写操作都有上下文，不再是盲批）。

行为对照

  • 允许一次本次放行，下次仍询问
  • 拒绝明确禁止，模型被告知换一个方案
  • 取消用户暂不决定，中止本次工具调用

P1 · 新增「完全访问」+ 风险确认

对齐 DSH 原生三档：只读 / 工作区可写 / 完全访问（danger-full-access：无沙箱限制、从不审批）。

界面改动

  • 左下角权限控件从原生 <select> 升级为自定义菜单（与模型选择器同一交互语言：单击展开、点击外部消失）。
  • 新增第三档 ⚠ 完全访问，选中后不会立即生效，先弹出红色风险确认框。
  • 风险确认框必须勾选「我已了解风险」才能点「启用完全访问」——与 DSH 客户端 RiskConfirmation 行为一致。
  • 触发按钮在完全访问档变红，持续警示。
  • 沿用现有约束：任务运行中禁止切换；切换在下一条消息的 Host 边界生效。

误操作或恶意提示词可能导致数据丢失或泄露。建议仅在可信任务中临时开启。

P2 · 沙箱 / 审批策略透明化

问题：现在用户看不到每档背后到底是什么。DSH 的权限实际是 沙箱级别 × 审批策略 的组合，界面应如实呈现。

界面改动

  • 菜单每项显示两行：名称 + 策略明细（沙箱级别 ｜ 审批策略）。
  • 菜单底部显示当前生效组合的一句话说明。
  • 触发按钮 hover 提示同步显示明细（tooltip：沙箱: workspace-write · 审批: ask）。
  • 为将来 DSH 的 custom 组合（用户自行改配置导致不匹配任何预设）预留展示位。

P3 · 「始终允许」会话级记忆

问题：只读模式下同类操作反复弹审批（装个依赖要批 5 次 Bash）。Codex / Cursor 都有「始终允许」。

界面改动

  • 审批卡片新增 始终允许：本次会话内同名工具（如 Bash）后续自动放行。
  • 放行后输入框上方出现记忆指示条，列出已自动允许的工具，可一键清空（点 ✕）。
  • 记忆只存内存：会话切换、权限模式变更、扩展重载即清空，不落盘（避免遗留授权）。
  • 「完全访问」档不显示审批卡片，记忆条自动隐藏。

安全边界

  • 记忆按工具名粒度，不是"全部放行"：允许过 Bash ≠ 自动允许 Write。
  • 切回「只读」或切到「完全访问」时立即清空。
