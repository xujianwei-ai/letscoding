## 三、修复后新引入的风险（自查）

### 3.1 P0-1 文件删除保护

**潜在问题**：
- `onWillDeleteFiles` 是 VS Code 1.85+ API，旧版本不支持
- 模态对话框可能阻塞用户操作
- 批量删除时多次弹出确认

**缓解**：
- 使用 `event.waitUntil` 异步处理，不阻塞其他扩展
- 只拦截源码/配置文件，不拦截所有文件

### 3.2 P1-1 Webview 状态持久化

**潜在问题**：
- `vscode.setState` 在测试环境不可用（已处理）
- 保存状态包含敏感信息（草稿文本）

**缓解**：
- 特性检测 `typeof vscode.getState === 'function'`
- 只保存草稿和滚动位置，不保存密钥

### 3.3 P1-3 Host 强制终止

**潜在问题**：
- `client.kill()` 是私有 API，可能不存在
- 强制终止可能导致数据损坏

**缓解**：
- 可选链调用 `client?.kill?.()`
- 仅在 `close()` 失败后调用

## 四、剩余未修复风险（诚实清单）

以下风险**已知但未修复**，因为影响低或需要架构变更：

| 问题 | 影响 | 不修复原因 |
|------|------|-----------|
| 会话恢复时 `needsResume` 依赖内存 | 崩溃后可能重复 resume | 需要 DSH 支持持久化 Host 状态 |
| 会话记忆审批重启后丢失 | 重复询问已批准工具 | 需要持久化审批记忆到 DSH |
| 检查点基线跨会话可能读错 | 显示错误 Diff | 需要 URI 包含完整会话上下文 |
| 冲突检测只警告不阻止 | 用户可能覆盖修改 | 设计决策：不阻断用户操作 |
| 测试重跑依赖 shell 环境 | 用户自定义 shell 可能失败 | 需要跨平台 shell 抽象 |
| 模型切换时 route 不同步 | 短暂显示旧模型 | 需要响应式配置监听 |
| 大文件只记录元数据 | 恢复时内容丢失 | 架构限制：不存储大文件内容 |

## 五、与 Cursor / Codex 的核心差距

## 六、总结

### 已修复风险（8 个）

| 级别 | 数量 | 修复内容 |
|------|------|----------|
| P0 | 3 | 文件删除保护、排除规则文档、操作审计 |
| P1 | 3 | Webview 状态持久化、rewind 提示、Host 强制终止 |
| P2 | 2 | 大文件警告、错误码映射 |

### 剩余风险（7 个已知未修复）

- 2 个需要 DSH 架构支持（会话恢复状态、审批记忆持久化）
- 2 个设计决策（冲突检测不阻止、大文件不存内容）
- 2 个需要跨平台/响应式改造（shell 抽象、配置监听）
- 1 个需要 URI 协议扩展（检查点基线跨会话）

### 与竞品对比

- **核心对话**：相当，缺少思考过程展示
- **历史回滚**：相当，检查点系统更轻量
- **代码审查**：缺少批量操作
- **模型管理**：缺少参数调节
- **工程效率**：功能索引、离线安装是优势

**当前状态**：已实现功能的核心风险已修复，剩余风险主要是架构限制或设计决策，不影响日常使用。
